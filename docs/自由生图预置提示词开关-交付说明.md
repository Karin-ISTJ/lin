# 自由生图「预置提示词」诊断与开关 — 交付说明

**版本**：`miya-image-gen.js v18` ｜ `miya-imagegen-app.js v4` ｜ SW 构建 `sw-97` ｜ 日期：2026-09

---

## 一、问题现象

自由生图输入「小麦」的提示词，却生成出一张二次元男主。

## 二、诊断结论：是，生图有预置提示词拼接

正向提示词由 `buildPromptBundle` 组装，**联系人生图与自由生图共用同一条链**，拼接顺序：

| 段 | 来源 | 说明 |
|---|---|---|
| 1 | **全局正向提示词**（生图设置 →「提示词与尺寸」） | **每张图都拼在最前，自由生图也不例外**。在这里存过二次元角色描述、或载入过「提示词预设」（载入会直接覆盖这个字段）就会污染所有图 |
| 2 | 性别标签（`1boy/1girl…`） | 仅联系人生图，按角色性别自动加 |
| 3 | 联系人自定义词 **或** 角色人设前 600 字 | 仅联系人生图 —— 人设是二次元男主时，画什么都带男主外貌 |
| 4 | 用户输入的场景描述 | 「小麦」在这里 |
| 5 | 固定画质词 | `masterpiece, best quality…`（无害） |

本次已排除的嫌疑：中文翻译词典（`miya-image-gen-dict.js`）无「小麦」条目，且原则「宁可漏不可错」，不会翻出人物标签。

**对照**：如果你的场景是让角色发图（聊天/朋友圈），那是第 3 段人设外貌拼入所致，属于角色一致性的既有设计；如果在生图 App 里自己输的「小麦」，那就是第 1 段全局正向词的锅 —— 打开「生图设置 → 提示词与尺寸」看看「正向提示词」框里是不是有历史内容。

## 三、本次改造

### 1. 自由生图新增「包含预置提示词」开关（默认开，保持旧行为）

- 位置：生图 App → 自由生图 → 画面描述上方
- **关闭后走「纯净模式」**：不拼全局正向/反向词，只按你输入的描述 + 基础画质词出图 —— 输入「小麦」就是纯麦田
- 开关单独存 `localStorage`（key：`miya-image-gen-free-nopreset-v1`），不进生图配置，不牵连备份迁移
- **联系人生图不受此开关影响**（人设外貌是角色一致性的核心，不能丢）

### 2. 「实际发送的提示词」透出（透明化）

生成完成后，结果卡片新增折叠区「实际发送的提示词」，展开可见实际发送的**正向/反向全文** —— 预置词、人设外貌拼了什么、拼在第几段，一眼可见，不用再靠猜。
实现上沿用 `blob.miyaRefFellBack` 的先例：`generateImageForScene` 把最终 prompt 挂在 `blob.miyaPrompt / blob.miyaNegative` 上，零接口变更。

### 3. 内部变更

- `buildPromptBundle(contactId, sceneDesc, opts)` 增加第三参 `opts.clean`：跳过第 1/2/3 段预置（签名向后兼容，旧调用不受影响）
- `generateImageForScene` 支持 `overrides.noPreset` 透传

## 四、验证

`node --check` 语法校验通过（`miya-image-gen.js` / `miya-imagegen-app.js` / `sw.js`）。

建议的自测路径：
1. 生图设置 →「提示词与尺寸」→ 检查/清空「正向提示词」里的历史内容
2. 自由生图输入「小麦」→ 关掉「包含预置提示词」→ 生成 → 展开 「实际发送的提示词」确认只有你的描述 + 画质词
3. 让角色发图，确认联系人生图行为不变（仍带人设外貌）
