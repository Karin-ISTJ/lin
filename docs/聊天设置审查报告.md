# 聊天设置审查报告

> 审查范围：聊天设置主面板（miya-chat-contact-settings.js）及其关联模块（global-settings / settings-panel / backup / storage-usage / heartvoice-templates / chat-store 保存链路）
> 审查方式：代码审读 + 真实浏览器（Playwright/Chromium）三轮复现验证
> 结论先行：**发现 1 个已实锤的高危数据破坏 bug、2 个中危问题、若干低危与体验不足**；整体架构与防御注释质量较高，但「子视图 × 顶栏保存」这一交互组合存在系统性防护缺口。

## 二、🔴 BUG-1（高危）：子视图内顶栏「保存」清空根级设置

### 根因链

1. 顶栏「保存」按钮在 `ensurePage()` 的 header 里**无条件渲染**（`miya-chat-contact-settings.js:1627`），进入子视图后仍然可见、可点；
2. 点击委托 `if (e.target.closest('[data-mq-set-save]')) { saveForm(); return; }`（`:3527`）**没有 `state.subView` 守卫**；
3. `saveForm()` 读取 `[data-mq-set-body]` 容器——子视图状态下该容器里**只有子视图 DOM**，根页的所有控件都不存在；
4. `readForm` 各读取器对缺失控件的兜底全部是「空值/关闭/默认值」：`isToggleOn` → false、文本框 → `''`、`activeIntervalMin` → `|| 30`；世界书排序读取器对缺失列表直接返回 `[]`；
5. 这些空值经 `saveChatSettings` / `applyContactOverride` / `setContactWorldbookEntryOrder` **真实落库**。

讽刺的是 `render()` 里的注释（`:3313-3317`）表明开发者已经注意到「顶栏保存会在子视图里触发重绘」，只是没有意识到它同时在**写坏数据**。

### 复现证据（三轮，Chromium 真实浏览器）

**第一轮**：根页设置备注/免打扰/天气感知/时间感知/语音 ID → 根页保存固化 → 进「对话 API」子视图 → 点顶栏保存 → 落库数据 diff：

| 字段 | 保存前 | 点顶栏保存后 |
|---|---|---|
| `remarkName`（备注） | `"测试备注-勿动"` | `""` **被清空** |
| `muteNotifications` | `true` | `false` **被关闭** |
| `onlineNarrationInjectContext` | `true` | `false` **被关闭** |
| `minimaxVoiceId` | `"voice_demo_001"` | `""` **被清空** |
| `weatherAwareness.enabled` | `true` | `false` **被关闭** |
| `timeAwareness.enabled` | `true` | `false` **被关闭** |

**第二轮**：预置该联系人已脱离全局默认（主动发消息开、45 分钟间隔、静默 21:40-6:40 开启）→ 子视图内点顶栏保存：

| perContact 覆盖字段 | 保存前 | 点顶栏保存后 |
|---|---|---|
| `backgroundMessage.activeEnabled` | `true` | `false` **主动发消息被关** |
| `backgroundMessage.quietEnabled` | `true` | `false` **静默被关** |
| `backgroundMessage.activeIntervalMin` | `45` | `30` **被重置为默认** |
| `memoryCount` | `120` | `120`（有 fallback，幸免） |
| `quietStartMin / quietEndMin` | `1300 / 400` | `1300 / 400`（有 fallback，幸免） |

**第三轮**：创建 2 个世界书条目并自定义排序 → 子视图内点顶栏保存：

```
worldbookEntryOrder: ["wb_mu7yk7af_…", "wb_mu7yk7ad_…"]  →  []   排序被清空
```

### 影响面评估

- 触发动作**极其自然**：用户进「对话 API」改完模型/密钥，想保存时第一反应就是点右上角「保存」——而这个动作会把他的备注、免打扰、天气感知、时间感知、语音 ID、主动发消息、世界书排序全部静默重置，**无任何确认或提示**。
- 波及所有 7 个子视图（api-chat / api-voice / api-image / backup / storage / notify / chat-defaults）。
- 未受影响（有防护，已验证）：emoji 分组（`emojiValid` 守卫）、`profileId`（空串不触发 `updateChat`）、memoryCount/summaryTrigger/summaryLength/quiet 时段（数值 fallback）。

### 修复建议（按侵入度从小到大）

1. **最小修复**：`saveForm()` 开头加 `if (state.subView) { saveSubViewForm(); return; }`——子视图内顶栏保存自动转为保存当前子视图，语义最顺；
2. 或者在 `saveForm()` 开头 `if (state.subView) return;` 并在子视图内隐藏顶栏保存按钮；
3. **配套加固**（防止同族问题复发）：
   - `saveForm` 对 `worldbookEntryOrder` 补 `length` 守卫（对齐 `applyFormDraft:1960` 的既有守卫，即 DEF-5）；
   - `readForm` 各读取器在关键控件缺失时抛错或返回 null（fail-fast），而不是静默给默认值——「根页表单不完整」本身就不该被当成合法输入。

## 三、🟡 BUG-2：storage-usage 模块的未定义引用（搬迁残留）

`js2/miya-storage-usage.js` 从设置 App 搬出时丢了几处定义，该文件是 `'use strict'`，以下引用一旦执行立即抛错：

| 位置 | 问题 | 触发条件 |
|---|---|---|
| `:430` | `invalidateApiPresetsCache()` **全文件未定义** → ReferenceError（且发生在分类清理的收尾阶段，会导致「系统与接口」清理后 apiPresets 内存缓存不失效） | 调用 `miyaStorageUsage.clearCategory('api')` |
| `:475` | 导出接口 `deleteAllChatImages` 指向**未定义函数** → TypeError | 调用 `miyaStorageUsage.deleteAllChatImages(items)` |
| `:259-261 / :481` | `invalidateStorageCache` 引用**从未声明的** `storageContextCache` / `storageContextPromise` / `storageSummaryHydrated`（严格模式下给未声明变量赋值抛 ReferenceError） | 调用 `miyaStorageUsage.invalidate()` |
| `:467` | `collect(force)` 的 `force` 参数被忽略——`collectStorageContext` 无参数、也无任何缓存机制，注释承诺的「force=true 绕过缓存」没有对应实现 | 无危害，文档与实现不符 |

当前 UI 只调用了 `collect / CATALOG / formatBytes / collectChatMediaImages`，所以以上都是**潜伏地雷**（无用户可见故障），但只要后续把「分类清理」「图片删除」接到 UI（UI-2 正需要这个），就会立刻踩中。

**修复建议**：删掉/补齐这三处——`invalidateApiPresetsCache` 改用 `miyaApiPresets.invalidate`（backup 模块 `:77` 有现成写法）；`deleteAllChatImages` 补实现或从导出中移除；`invalidateStorageCache` 相关变量与缓存机制要么补全、要么整个删除（当前 collect 本就无缓存，直接删最干净）。

## 四、🟡 BUG-3：备份导入非原子，中途失败无回滚

`js2/miya-backup.js`：

- `applyBackupLocalStorage`（`:427-444`）第一步就 `localStorage.clear()`，然后逐 key 写入。若中途配额不足/页面被杀：**旧数据已清、新数据只写了一半**，有 failed 计数提示但没有回滚，clear 与写入之间不存在任何安全点。
- ZIP 导入路径的写入顺序是「IDB/扩展数据先写 → localStorage.json 最后写（88% 阶段）」，中途失败会留下「IDB 新 + localStorage 旧」的混合状态。

做得好的部分（对比参考）：导入前有「将覆盖当前全部本地数据」确认框、进度反馈完整、导入后建议刷新、失败有计数提示。

**修复建议**（最小改动）：
1. 导入 localStorage 前先把当前 `localStorage` 全量快照到内存（或先触发一次自动导出留底），失败时回写快照；
2. 或至少在 clear 之前校验备份数据总量 ≈ 可用配额（`navigator.storage.estimate()`），明显超限就直接拒绝导入并提示。

## 五、🔵 体验不足与防御缺口

### UI-1：语音合成的模型下拉是「死」的
`#mq-voice-model` 只渲染当前值一个 `<option>`，也没有「对话 API」两个下拉那样的 ⟳ 拉取按钮——**模型只能看不能换**。本次第六批修复给 `#mq-api-model` / `#mq-api2-model` 建好的「缓存 + hydrate + 草稿」三层机制，语音下拉一件都没接。

### UI-2：存储子视图的聊天图片区只有标题
`refreshStorageSub`（contact-settings `:3281-3287`）对图片区只输出「聊天图片（N 张）」一行标题，没有列表、没有压缩/删除入口。数据层的 `compressAllChatImages` 已经实现且有 `invalidateBlobUrl` 配套，**只差 UI 接线**（注意接线前先修 BUG-2，否则 `deleteAllChatImages` 直接 TypeError）。

### UI-3：多选 JSON 备份只处理第一个
`importBackupJson(jsons[0])`（backup `:728-730`）：文件选择框开了 `multiple`，用户多选 JSON 时其余文件被静默丢弃、无提示。

### DEF-4：`applyContactOverride` 只剔除 `CHAT_LEVEL_BM_KEYS`
（global-settings `:187-195`）没有像 `applyToChatSettings` 那样同时剔除 `SESSION_SCOPED_BM_KEYS`（farm/timeEvents）。当前唯一调用方 `saveForm → readConfigScopedMemory` 传入的是干净构造的 bgPatch，所以**现在没事**；但它是导出的公共 API，任何新调用方传入完整 `backgroundMessage` 就会把会话级农场/时间线数据冻结进 perContact——注释里写过「farm 和 timeEvents 已经各踩过一次」，建议两份清单一并剔除，堵住复发路径。

### DEF-5：世界书排序的防护不对称
`applyFormDraft:1960` 有 `draft.worldbookEntryOrder.length` 守卫（知道空数组是「无数据」信号），`saveForm:2069` 却只判 `Array.isArray`——空数组照样落库。这正是 BUG-1 世界书清空路径的直接缺口。

## 六、审查中确认「无问题」的部分

- 温度/语速/音量/音调滑块的 label 同步完整（input 委托 `:3951-3969`）；
- 美化预设两步交互（选预设 → 点「读取预设」）无中间态丢失；
- 心声模板选择器同步渲染选项；已删除预设名落空时显示为「系统默认」，可接受；
- `miya-chat-global-settings.js` 的字段剔除双清单 + 详尽文档，`applyToChatSettings` 合并语义正确；
- `miya-chat-settings-panel.js` 指路页与 `mountDefaultsInto` 的「每次全新重建」模式正确，无重复绑定；
- 备份模块导出/导入有确认框 + 进度 + 失败计数；「一键清空全部数据」已按需求移除且未留后门；
- notify 子视图对 `miya-msg-sound.js` 按 `getElementById` 全局查找的 id 硬约束有明确注释，ids 与原版一致。

## 七、修复优先级建议

1. **立即**：BUG-1（一行守卫 `if (state.subView)` + 可选的世界书 length 守卫）——数据破坏面最大、触发最自然、修复成本最小；
2. **随后**：BUG-2（storage 模块 3 处未定义引用，接线 UI-2 前置条件）、BUG-3（导入回滚或配额预检）；
3. **排期**：UI-1（语音模型下拉接入三层机制，可复用第六批成果）、UI-2（图片压缩 UI 接线）、UI-3（多文件提示）、DEF-4（剔除清单补全）。
