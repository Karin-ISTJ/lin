# 线下流式缺字根治 · 交付说明

> 对应反馈：「线下剧情流式输出过程中内容会缺几个字，等输出完成后才显示完整的内容。」
> （老问题，与近期改动无关 —— 确实，这是流式渲染 diff 的原生缺陷，这次一并根治。）

## 一、根因

流式渲染的段落补丁（`patchStreamMount`）按**段落数量**对齐 DOM，且**只更新最后
一段**（正在打字的 live 段）—— 前面的段落 append 之后**永不改写**。

而段落切分（`splitDisplayParagraphs`）有条降级规则：
**按双换行（空行）只切出 1 段时，改按单换行切**。流式中模型补出第一个空行的
瞬间，切分整体跳变：

```
之前  "甲段。\n乙"          → 降级单换行 → ["甲段。", "乙"]            （P0=甲段。 P1=乙）
之后  "甲段。\n乙\n\n丙段。" → 空行出现   → ["甲段。\n乙", "丙段。"]    （P0 应为「甲段。乙」）
```

段落数都是 2，旧 diff 按"数量没变"就认为内容没变 —— 只有 P1（live）被更新，
**P0 停在旧内容，「乙」二字从流式画面里消失**，直到生成结束楼层全量重建才回来。
任何段落边界后移（空行补写、时间线前缀剥除窗口变化）都会触发同类缺字，
表现为"缺几个字"，位置和字数随排版变化。

## 二、修复：按数量对齐 → 逐段内容对齐

`js1/miya-appointment-app.js`（`?v=158 → 159`）的 `patchStreamMount`：

1. **数量对齐以真实 DOM 为准**（`existing.length`），不再依赖记忆计数 ——
   DOM 是事实源，任何状态漂移下一帧自动纠正；
2. **每帧把每一段的期望 HTML 与现有 `innerHTML` 对比，变了才写**：
   - 段落通常不到几十个、揭示步进每帧 2~24 字，逐段对比成本可忽略；
   - "变了才写"保住 DOM 复用 —— 不重建节点，**无白闪、滚动不跳**；
3. `data-ap-stream` 索引属性随文档序同步修正；live 类依旧恰在最后一段。

线上聊天的流式渲染**没有**这个 diff 模式（整段重绘），无需改动。

## 三、验证（Node 单测 12/12 通过，`_test_stream_diff.js`）

- **[A] 旧逻辑重现**：同一流式序列下，P0 确实停在旧内容、缺「乙」——
  证明根因判断准确；
- **[B] 新逻辑修复**：提取真实 `patchStreamMount` 源码 + 真实
  `splitDisplayParagraphs` 跑同序列，每段 innerHTML 与期望逐字一致，「乙」回来；
- **[C] 常规空行分段**（边界不移动）行为不变；
- **[D] 打字机未追平时**（揭示截断态）逐段对齐依旧正确；
- **[E] live 类恰好只标最后一段、索引属性与文档序一致**；
- **[F] 段落数回退**（重新生成截短）时节点正确删除、内容正确。
