# 现实时钟事件 · 使用说明

> 这个功能解决的是：**剧情可以跳天，但现实时间是真的在走。**
>
> 你在第七天存了一笔定期，约好七天后取利息；结果你隔了一周才回来接着过剧情。
> 按以前的写法，角色只能「陪你演」——他又不能真的等七天。
> 现在利息会按**你手机上的真实时间**到期，你回来的那一刻，正文上方自动弹出一张到账卡。

---

## 一、它和「剧情里的时间」有什么区别

两套时间是**分开**的，互不干扰：

| | 剧情时间 | 现实时钟 |
|---|---|---|
| 谁在走 | 角色和你在故事里过的时间，一天可以跳好几章 | 你手机上真实流逝的时间 |
| 存在哪 | 对话内容里 | 独立账本，跟你聊到哪句毫无关系 |
| 你不在的时候 | 停住 | **照常走** |
| 表现 | 正文描述 | 正文**上方**的系统卡片 |

所以会出现这种情况，而且是正确的：

> 虚拟剧情里才过了一晚，但现实里你已经隔了三天没打开。
> 那三天该到的东西，会在你回来时一起结算给你。

---

## 二、你会看到什么

当有事情到点时，线下场景的**正文上方**会出现卡片，长这样：

```
┌─────────────────────────────────┐
│ 🏦 待确认            9/8 15:58  │
│ 定期存款利息                     │
│ 存入后 7 天可领取利息            │
│ ───────────────────────────────  │
│ 到账 +86 铜币                    │
│ 已过去 7天                       │
│ [ 领取 / 确认 ]                  │
└─────────────────────────────────┘
```

三种状态，一眼能分清：

| 徽章 | 含义 | 你要做什么 |
|---|---|---|
| **待确认** | 事情成了，但需要你点一下才算数 | 点「领取 / 确认」 |
| **已到期** | 事情成了，没有你要做的手续 | 点「知道了」收起来 |
| **已错过** | 过期太久，这件事作废了 | 点「知道了」，角色不会再提 |

卡片上那行 **「已过去 7天」** 就是它和普通剧情奖励最大的区别——它诚实告诉你：这件事的到期时间早就过了，是你现在才回来。

---

## 三、哪些事能记进账本

**只接受「本身就需要现实等待」的事**，这是硬规则：

| 类型 | 例子 |
|---|---|
| 🏦 银行利息 | 定期存款到期 |
| 📈 投资结算 | 基金/理财到期 |
| 💼 工资 | 发薪日 |
| 💸 退款 | 退货到账 |
| 📦 快递 | 买东西等到货 |
| 🔧 维修 / 委托 | 送修、托人办事 |
| 📋 申请 / 审核 | 等审批结果 |
| 📅 预约 | 约好的时间点 |
| 🎫 演出 / 电影 | 开演时间 |
| 🌱 种植 / 发酵 | 等它长/发酵 |
| ✈️ 旅行 / 🏆 比赛 / 📝 考试 | 到点发生的事 |

**明确不接受**（会直接被拦掉，不显示也不记账）：

- ❌ 礼物、惊喜、告白、「给你准备了什么」
- ❌ 任何不需要等就能立刻给你的东西

道理很简单：**能立刻给的东西，凭什么要你等？**
只有真的需要等待的事，才配得上「过几天再来」这个体验。

## 四、怎么让角色卡用上它

事件是模型在回复里主动声明的。你需要在**角色卡的世界书**里加一条规则，告诉它什么时候、用什么格式写。

### 复制区（把下面整段加进世界书）

```
【现实时钟事件】

当剧情中出现「需要现实时间等待才有结果」的事（存钱生息、买东西等发货、
送修、等审批、约好的时间点、种植发酵等），在回复末尾追加一条事件声明，
格式如下（必须是合法 JSON，单独占一行）：

<miyaevent>{"type":"bank_interest","title":"定期存款利息","description":"存入后 7 天可领取利息","result":"到账 +86 铜币","afterDays":7,"needsClaim":true}</miyaevent>

字段说明：
- type：事件类型，可选值——
  bank_interest（银行利息）/ investment（投资结算）/ refund（退款）/
  salary（工资）/ settlement（结算）/ delivery（快递）/ subscription（会员订阅）/
  lease（租期）/ plant（种植）/ fermentation（发酵）/ repair（维修制作）/
  commission（委托）/ application（申请审核）/ appointment（预约）/
  ticket（演出电影）/ match（比赛）/ travel（旅行）/ exam（考试）/ general（事务）
- title：事件名，简短
- description：补充说明（可省略）
- result：到期时会显示成什么结果，比如「到账 +86 铜币」
- afterDays / afterHours / afterMinutes：从现在起多久后到期（三选一，填数字）
- needsClaim：true = 到期后需要用户点「领取 / 确认」；省略则到期直接算成

规则：
1. 不要在正文里播报这条事件。正文该写什么写什么，事件声明放在最后。
2. 只有真的需要等待的事才声明。立刻能给的礼物、惊喜、告白一律不要写。
3. 同一件事不要重复声明。
4. 一次回复最多声明 1~2 条，没有就不写。
5. 声明必须用 <miyaevent> 标签包住，标签外不要写别的 JSON。
```

### 配合角色说话的方式

光有格式还不够，模型得知道**为什么**要这么做。建议在这条规则里再加一句人话，比如：

> 用户可能隔好几天才回来继续剧情。到那时，这些事应该已经发生完了。
> 不需要为这件事强行跳过剧情时间——现实时间本来就在走。

## 五、几个常见问题

**Q：卡片会一直堆在正文上方吗？**
不会。你点「领取 / 确认」或「知道了」之后它就消失了。已领取的不再显示；已错过的点掉之后也不再出现。

**Q：角色会不会在正文里重复念叨这件事？**
不会。账本会同步给模型，并且明确标注「已错过的事禁止再提议现在去做」。所以角色不会在你回来时还催你「快去取利息」。

**Q：剧情跳天了，会影响真实到期吗？**
不影响，两者完全独立。剧情里过三天、现实里过三天，是各算各的。

**Q：我换手机 / 清缓存了还在吗？**
账本跟聊天记录存在一起，跟着你的数据走。清掉浏览器数据就没了——跟聊天记录一样。

**Q：旧消息里已经有 `<miyaevent>` 标记怎么办？**
不会显示出来。这层标记在存进楼层之前就被摘走了；历史里的残留也会在送进模型前清掉，不会污染正文，也不会被当成陈年事件重新入账。
