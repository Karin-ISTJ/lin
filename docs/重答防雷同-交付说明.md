# 重答防雷同 · 交付说明

针对用户多次反馈的「**线上和线下重新发送消息，都会生成和上次一模一样的内容**」。
此前已修过三轮（全部是提示词层修复），本次为第四轮，**从请求层和输出层根治**。

---

## 一、为什么前三轮修复没压住

前三轮的修复全部落在「提示词」上：

| 轮次 | 修复 | 位置 |
|---|---|---|
| 1 | 重回 nudge：明确「不是同义改写，要换方向」 | `miya-chat-engine.js` `buildRegenerateTailNudge` |
| 2 | 引用上一版原文，让「别重复」有对照对象 | 同上 + `readLastRawAssistantReply` 撤回快照 |
| 3 | 线下补【重答要求】提示块 + 第 N 次重答计数 | `miya-appointment-engine.js` `buildRegenerateHintBlock` |

方向没错，但有一个共同盲区：**从头到尾没有任何一处验证过「新回复是否真的和上一版不同」**。
提示词只是祈祷，输出侧没有闭环。

而且有两颗提示词永远压不住的雷：

1. **中转站/网关的请求级缓存**。大量 OpenAI 兼容中转为了省钱，会按请求体哈希
   缓存 completion——短时间内同 body 的请求直接回放缓存内容。
   线上重答的 nudge 引用「上一版原文」，一旦第 1 次重答就和原版一样
   （温度低时很常见），第 2 次重答的上下文与 nudge 引用文本就与第 1 次
   **逐字节相同**——网关直接把缓存吐回来。
2. **采样参数零差异化**。temperature 固定取自 ST 生成设置、没有 seed、
   没有重答分支。用户预设温度为 0~0.2 时，「输入几乎相同 + 贪心解码」
   在长 system + 强人设锚定下完全可以逐字复现——nudge 只是末尾一小段，
   压不过几千字的上下文锚。

## 二、本次修复：三层机制（缺一不可）

> 线上 `miya-chat-engine.js` 与线下 `miya-appointment-engine.js` 同构实现。

### 机制① 请求唯一化（防任何一层缓存）

每次重答请求在 messages 末尾注入一条唯一的「**系统内部查重码**」
（时间戳 + 随机数的 base36，再叠加尝试序号），并显式告知模型
「仅供系统区分请求，禁止回应/提及/输出」。

效果：**请求体逐字节永不重复**。任何按 body 哈希做缓存的中转/网关
都不可能再回放缓存的旧回复。

### 机制② 采样差异化（防低温度贪心收敛）

仅重答请求：温度上浮 `+0.15 × 尝试序号`，上限 1.6。

- 只作用于重答这一个请求、只往多样性方向推；**普通发送的采样参数一字不动**；
- 刻意**不发 seed**：seed 的语义是「可复现」，与重答要的「不可复现」正好相反，
  且个别严格网关会对非预期字段报 400，得不偿失。

### 机制③ 输出查重闭环（真正的兜底保证）

生成成功后，把**新正文与上一版**做归一化比对：

- 归一化：剥思维链 / `<miyavoice>` / 状态栏 / 推送标签 / 剩余标签，
  去掉全部空白与全半角标点，转小写，截 2400 字；
- 判雷同（命中任意一条）：
  1. 归一化后完全相等；
  2. 字符二元组（bigram）Dice 相似度 ≥ 0.88；
  3. 较短一方 ≥ 24 字且被较长一方完整包含
     （抓「旧文原样 + 尾巴补一句」的偷懒形态）；
- **判定雷同 → 自动换向重试**，请求附带【系统查重】系统块
  （直接告知「上一版未过查重、用户不会看到」，并给出可执行的换向要求）
  + 温度再上浮 + 新查重码，最多 3 次；
- 全部雷同就交付最后一版（此时机制①②已尽力，不会再无限烧钱）。

**机制③是唯一能保证「用户看到的和上一版不一样」的一层——
因为它验证的是结果本身，而不是指望模型听话。**

实测标定（避免误杀正常重写）：

| 情形 | Dice | 判定 |
|---|---|---|
| 逐字复读 / 换皮复读（剥标签后相同） | 1.000 | 雷同 ✔ |
| 旧文原样 + 尾巴补一句 | 0.659~0.862 | 雷同 ✔（包含规则命中） |
| 真正换向重写 | ≈ 0.00 | 不同 ✔ |
| 同一情节、措辞大改 | 0.036 | 不同 ✔ |

## 四、行为与实现要点

- **线下隐藏重试不打扰界面**：查重未过时的重试摘掉 `onDelta/onLine/onPartial`、
  改走非流式一次性取回，完成后照常走楼层替换——界面收尾
  `patchStoryBody` 时直接呈现新版，不会出现两段字叠着蹦；
- **上一版正文的采集时机**：线下调用方（`regenerateAssistantFloor` /
  长按重发）在**软删楼层之前**抓 `m.content` 经 `opts.prevContent`
  传入引擎（软删会清空 content，晚了就没了）；
- **线上快照只消费一次**：`sendChat` 在 `buildApiMessages` 之前统一取走
  撤回快照（`readLastRawAssistantReply` 是「取一次即清」），再经
  `opts._regenCtx.prevRaw` 递给 nudge 复用，避免双重消费导致引用块凭空消失；
- **控制台可观测**：查重重试会留痕 `[regen]` / `[offline regen]` warn，
  便于用户报障时定位；
- 机制①②对「非重答」的普通生成零影响；机制③只在查重基线非空时生效。
