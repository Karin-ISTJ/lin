# Karin · 线下候选的记忆延迟写入

本次改动只做一件事：**线下一层角色回复有多个候选（`‹ ›` 翻看）时，记忆表不再串味。**

全部改动带可重跑回归，并通过 A/B 对照验证（把实现改坏，测试必须变红）。

---

## 一、修的是什么问题

### 现象

线下一层角色回复可以点右下角 `‹ ›` **翻出好几个候选版本**。
翻回旧候选、继续发消息，会遇到两个症状：

| 症状 | 你看到的 |
|---|---|
| **串味** | 界面显示的是第 1 版，记忆表里却是第 2 版写的内容 |
| **凭空消失** | 生成第 2 版时，第 1 版写过的记忆被一起清掉了 |

### 根因

候选**共用同一个消息 id**。点 `›` 时引擎用 `replaceTargetId: m.id`
把新一版写回**同一层**，id 不变 —— 而记忆表的行溯源（`rowSource`）
记的就是这个 id，于是它**无法区分候选**：

- 生成候选 B 时软删原行 → 按 id 回收 → A 的记忆被连带清掉
- 翻回 A 再发消息 → 界面是 A，但记忆表停在 B

## 二、现在的规则

> **你不选定，就不写。**

| 你做的事 | 记忆表什么时候更新 |
|---|---|
| 生成一版，没有再翻候选 | 生成完**立即写** |
| 点 `›` 翻出候选 | **先不写**，等你选定 |
| 翻看候选（`‹` `›` 来回看） | **不写**（翻看不等于选定） |
| **在某一版下面继续发消息** | 这时才把**那一版**的记忆写进去 |
| 在历史楼层（下面已有别的内容）重生成 | **立即写**（早被钉住，不参与延迟） |

「往下写」才代表「我认了这一版」—— 翻看不做数（翻完可能又翻回去）。

### 顺带的正确行为

生成候选时，原版变成候选 → **它先前写的记忆会被回收**。
这不是 bug，是必须的：否则「两条时间线」的记忆会同时留在表里。
你选定哪一版，就写哪一版。

### 关键设计：为什么要多存一个 `mtRaw`

正文里的 `<tableEdit>` 标记必须在**解析正文之前**就剥掉 ——
否则标签会顺着 content 写进楼层，下一轮又被当历史送回，模型开始照着模仿。

但剥掉之后就**再也解析不出**「这一版原本要写什么记忆」了。
而候选悬着时我们故意不落库，等用户选定再补写 —— 补写总得知道原文。

所以：

- `mtRaw` —— **当前显示那一版**的原始标记
- `swipeMtRaw` —— **各候选各自**的标记，与 `swipes` 按下标一一对齐

少了 `swipeMtRaw`（只留一份当前版的），翻回旧候选确认时就会写错版本 ——
这正是开发过程中真实踩到的一个 bug，已由静态断言 S26/S28 + A/B 守卫 A10-A12 守住。

## 四、这里的两个坑（给后来改这段的人）

### 1. 引擎内那条 `processAssistantReply` 才是落库主力

线下路径有**两处**会碰记忆表：

- 引擎解析正文前那处（`dryRun`，现在只剥离）
- 收尾的 `afterGenerate`（线下走 `result.message.content`，已剥离，解析不出动作）

早先延迟门只包住了 `afterGenerate`，看着像做了，实际**根本没生效** ——
真正把候选版写进表里的是前一处。加门时必须同时看这两处。

### 2. 平行数组的条件不能「抄」

`prevSwipes`（候选正文）和 `prevSwipesMtRaw`（候选标记）是按下标对齐的。
给标记补一条时，条件**不能照抄正文那句的 `!prevSwipes.length`** ——
正文那句已经先跑过，到标记这步这个条件恒假，标记一次都补不上。
现在两处 push 合并进**同一个 if**，从根上避免。

## 五、测试

| 测试 | 断言 | 覆盖面 |
|---|---|---|
| `test/audit_swipe_defer_gate.py` | 64 | 判据运行时行为（20）、引擎/App/记忆表接线（S1-S33）、A/B 反向守卫（A1-A14） |

浏览器测试走的是**用户真实路径**（`__testRegenFloor` / `__testApplySwipe` 后门 = 点 `›` / `‹` 的同一段代码），
不是测试自己另写一份 `updateMessage`。

A/B 守卫覆盖的反向变异（把实现改坏，断言必须变红）：

- 判据改恒 true / 恒 false
- 延迟门失效（`!deferMemory` → `false`）
- 补写挪到 `addMessage` 之后
- 漏传 `dryRun`（候选悬着照样落库）
- 不回传原始标记
- 白名单漏掉 `swipeMtRaw`（字段被静默丢弃）
- 归档正文但漏归档标记
- 补写改用被剥离过的 `content`

### 顺带修的两处测试基建

- `test/run-all.py` 的服务判据只认 `localhost:80xx`，漏了一大批写 `127.0.0.1:8099`
  的脚本 —— 它们被当成「纯静态」先跑，那时服务还没起，稳定报连接失败。
  现在两种写法都认，并把 `playwright` 也算信号。
- 同一文件的结果解析不认 `N/M 通过` 这种紧凑格式，
  于是线下那几个 e2e 的断言数一直是 `-`。已补上。
