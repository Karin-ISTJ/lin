## 三、卡片显示位置（为什么这样选）

挂在 `renderStory()` 与 `patchStoryBody()` 两处的 `renderStoryLines(...)` 之后、流式挂载点之前：

- **在正文之后** —— 用户得先读完这一镜，才谈得上「接下来怎么走」；
- **在流式挂载点之前** —— 否则生成中这块会不断被改写，卡片被顶来顶去，点不中；
- **场景级、不挂楼层** —— 挂每层会导致翻历史时满屏过期建议，点下去模型接的是另一段情节。

实测截图里，卡片确实是 `#mol-story-body` 的最后一个子元素（`lastChildClass: "xw-plot-card"`）。

## 五、几个刻意避开的坑

这些是读代码时发现项目历史上踩过、且本功能会直接命中的问题：

1. **`patchStoryBody()` 不重跑 `bindEvents()`**
   它只重写 `mol-story-body` 的 `innerHTML`。直接给按钮绑元素监听器 = 生成完就变成裸按钮。
   → 点击走 `bindFloorToolsDelegate()` 事件委托，与状态栏卡片同一套路。

2. **`renderStory()` 和 `patchStoryBody()` 是两条路径**
   两处都必须插入卡片 HTML，否则「首次进入」和「就地重写」表现不一致（历史上事件卡就吃过这个亏 ——「刚回来能看到，一说话就没了」）。

3. **`<plot>` 标记必须落库前剥掉**
   不剥的话下一轮会被当历史送回，模型会照着格式再吐一遍（`<tableEdit>` / `<miyaevent>` 都踩过）。
   → 剥离放在 `finalizeAppointmentAssistantBody()` 里、**比状态栏还靠前**：越早摘掉，后面按行/按段处理的逻辑都不会把建议行卷进去。

4. **指纹不进 `computeStableStoryKey` 就会漏刷**
   切候选（‹ ›）时内容换了、建议也跟着换，但消息条数没动、`last.id` 也没动 —— 不带 `:ph` 指纹，`patchStoryBody` 判定「无变化」，卡片停在上一版建议上。
   → 与 `:fh`（楼层隐藏）、`:te`（时钟事件）同类处理。

5. **空数组必须能覆盖旧值**
   模型某轮没吐 `<plot>` 时引擎显式传 `[]`。若被当成「没传」跳过，卡片会挂着上一轮那批过期选项。

6. **点建议发送时不能抹掉输入框草稿**
   你点卡片时输入框里可能正写着别的东西。`sendMessage(presetText)` 只在「真的用了输入框里的字」时才清空它。

## 五、追加修复：项目内比独立 HTML 丑很多（字号爆炸）

### 现象

同一份卡片代码，单独用 HTML 打开好看，放进项目里变成另一副样子：

| | 卡片高 | 标题 | 字距 | 选项 |
|---|---|---|---|---|
| 修复前 | **863px** | **39.06px** | **7.03px** | **39.06px** |
| 修复后 | **317px** | **12px** | **2.16px** | **14px** |
| 独立 HTML | 316.8px | 12px | 2.16px | 14px |

> 修复后的数值与独立 HTML **完全一致**。

### 根因

`css/style.css` 里有一条全局字号缩放规则：

```css
[data-miya-fs] :where(
  p, span, div, li, a, button, label, h1, h2, h3, h4, h5, h6,
  td, th, dt, dd, blockquote, figcaption, small, time, em, strong, b, i,
  input, textarea, select, option, pre, code, cite, q, mark, sub, sup, legend
):not(.qq-room__msg-time):not(svg *):not([class*="icon"]):not([class*="Icon"])
:not(.material-icons):not(.ic):not(.ic *):not([data-i]):not(.foot__dock-btn)
:not(.ins-icon-pick__glyph) {
  font-size: calc(1em * var(--miya-font-size-scale, 1)) !important;
}
```

三个致命点叠在一起：

1. **带 `!important`** —— 普通的 `font-size` 声明一律被它压掉；
2. **命中所有后代标签** —— 卡片里每一层 `div` / `button` 都中招；
3. **用 `1em` 相对值** —— 每一层都相对父级再乘一次倍率。

用户在线下设置里把字号调到 125% 时，`miya-theme.js` 会给 `.miya-offline-app`
加上 `data-miya-fs` 并把 `--miya-font-size-scale` 设成 `1.25`。
卡片有 7 层嵌套，`12px` 一路 `×1.25` 滚上去，最终到 39~49px。

### 试错记录（都验证过，别重走）

| 尝试 | 结果 |
|---|---|
| `.xw-plot-card * { font-size: X !important }` | ❌ 无效，特异性 `(0,1,0)` 输给对家 `(0,10,1)` |
| 加长选择器到 `.miya-offline-app .xw-plot-card[..] .sec-title`（`(0,3,0)`） | ❌ 仍输 |
| 堆到 `[data-ap-plot-card][style]`（`(0,4,0)`） | ❌ 仍输 |
| 把 `--miya-font-size-scale` 在卡片上归零 | ❌ 部分有效，但 `1em` 仍取到上游已放大的计算值 |
| **内联 `style="font-size:12px !important"`** | ✅ **成功** |

> 关键认知：两个 `!important` 相撞时**只比特异性，不看书写顺序**；
> 而 **内联样式的 `!important` 是层叠里的最高一级**，CSS 文件永远追不平。
> 所以字号必须由 JS 内联输出，不能只写在 CSS 里。

### 改动

**`js2/miya-offline-plot.js`**

- 新增三个常量，集中管理字号绝对值：
  ```js
  var FIX_FS_15   = 'font-size:15px !important';
  var FIX_FS_12   = 'font-size:12px !important';
  var FIX_FS_14   = 'font-size:14px !important';
  var FIX_FS_13_5 = 'font-size:13.5px !important';
  ```
- `renderPlotCardHtml()` 把字号内联写到**卡片根 / .wrap / .sec / .sec-title / .choice** 五处；
- 根节点同时内联 `--miya-font-size-scale:1` 作双保险；
- 用 `matchMedia('(max-width:420px)')` 判定窄屏，选项输出 `13.5px`
  （因为内联值永远赢过媒体查询，媒体查询那条写了也不生效）。

**`css/miya-offline-plot.css`**

- 新增「字号免疫」段落，记录完整根因与试错过程；
- 只保留 JS 够不到的部分：伪元素字号（`::before` / `::after` 无法内联）与 `letter-spacing`。

**`index.html`**

- `miya-offline-plot.css?v=8`、`miya-offline-plot.js?v=4`（破 SW 缓存）。

### 验证

| 场景 | 标题 | 选项 | 卡片高 |
|---|---|---|---|
| 项目内 · 未调字号 | 12px | 14px | 317px |
| 项目内 · 100% | 12px | 14px | 317px |
| 项目内 · **125%**（原本爆炸） | 12px | 14px | 317px |
| 项目内 · **150%** | 12px | 14px | 317px |
| 项目内 · 85% | 12px | 14px | 317px |
| 独立 HTML（对照） | 12px | 14px | 316.8px |

125% / 150% / 85% 三档的**渲染截图 MD5 完全相同**（`2ec31ddb…`），
说明字号设置对卡片已零影响。

### 副作用（刻意接受）

用户在「线下」设置里调字号时，**这张卡片不跟着变大**。
理由：卡片是一套调好的成品设计（字号 / 字距 / 内边距 / 圆角是一个整体），
跟着缩必然重新变形，那就又回到「和独立 HTML 不一样」的老问题了。

## 六、按下特效（第二处修复）

### 你看到的差异是这样来的

你在独立 HTML 里点下去，按钮会「浮起来 + 紫描边 + 紫调阴影」。
那一套效果，**是 `:hover` 和 `:active` 同时命中**的结果 —— 桌面鼠标按下时两个伪类一起生效。

移植进项目后，原来的 `:active` 只有这两句：

```css
.xw-plot-card .choice:active {
  transform: translateY(0);
  box-shadow: none;
}
```

问题就在这：它**不是「加上按下态」，而是「把 hover 的浮起取消掉」**。
触屏没有 hover，于是 `:active` 成了唯一生效的规则，结果手指按下去 = 主动把效果清空，
**什么都不发生**。你感觉「我那个特效没了」，就是这么丢的。

### 改法

把 `:active` 补成一套**完整的按下态**，数值直接复用 `:hover` 的那组（保证两种设备手感一致）：

```css
/* ── 按下反馈 ──────────────────────────────────────────────────
   独立 HTML 里点下去会「浮起来 + 紫描边 + 紫调阴影」，
   那是因为桌面鼠标同时命中了 :hover 和 :active。
   触屏没有 hover，只靠原来那句 `.choice:active { transform: translateY(0);
   box-shadow: none; }` 等于「把浮起取消」—— 按下去反而什么都不发生。
   所以这里把 :active 补成一套完整的按下态。 */
.xw-plot-card .choice:active {
  transform: translateY(-2px);
  border-color: rgba(107, 78, 158, .38);
  background: #fff;
  box-shadow: 0 6px 16px -12px rgba(107, 78, 158, .55);
}
.xw-plot-card .choice:active::before { opacity: .9; }
```

顺带给 `::before`（那个 `◇`）加了过渡，让透明度变化不是硬切：

```css
.xw-plot-card .choice::before { transition: opacity .16s ease; }
```

### 实测数值（CDP `CSS.forcePseudoState` 强制伪类读取）

| | 描边 `border-color` | 阴影 `box-shadow` | `◇` opacity |
|---|---|---|---|
| 静止 | `rgba(107, 78, 158, 0.2)` | `none` | `0.55` |
| **按下** | **`rgba(107, 78, 158, 0.38)`** | **`rgba(107, 78, 158, .55) 0 6px 16px -12px`** | **`0.9`** |

做得不只是「读到了值」，还截了两态图对比：

- 「按下」与「桌面 hover」两张截图**字节数完全相同（51851）** → 触屏按下 = 桌面悬停，手感统一；
- 与静止态逐像素比对：**45060 个像素发生变化**，差异区域 `(48, 152, 1122, 329)` 正好落在目标按钮上，
  说明变化范围没有溢出、误伤其他元素。

预览图见 `剧情建议卡-按下特效.png`（左：静止；右：按下）。

### 回归

## 七、关于「颜色差那么多」

先给结论：**卡片本身的颜色两边完全一样。差的是卡片外面那层页面底色。**

### 实测数据

同一张卡、同一段文案、同一台设备（390×844，DPR 2），只改页面背景：

| 位置 | 项目内（线下 App） | 独立 HTML | 差值 |
|---|---|---|---|
| 卡片外·页面底色 | `rgb(247,247,245)` | `rgb(255,255,255)` | **+8, +8, +10** |
| 面板背景 `.sec` | `rgb(252,250,255)` | `rgb(252,250,255)` | **0, 0, 0** |
| 按钮背景 `.choice` | `rgb(255,255,255)` | `rgb(255,255,255)` | **0, 0, 0** |
| 按钮描边 `border` | `rgba(107,78,158,.2)` | `rgba(107,78,158,.2)` | **0, 0, 0** |
| 选项文字 `color` | `rgb(42,36,54)` | `rgb(42,36,54)` | **0, 0, 0** |
| 标题文字 `.sec-title` | `rgb(122,114,144)` | `rgb(122,114,144)` | **0, 0, 0** |

**卡片内部五个色值，逐通道全 0 差异。** 差别只出现在卡片外的背景区域。

### 那个"黄"是从哪来的

线下 App 的默认底色定义在 `css/miya-offline.css`：

```css
.miya-offline-app,
.miya-offline-app.xw-theme-museum {
  --xw-bg: #f7f7f5;     /* 暖灰，不是纯白 */
}
```

`#F7F7F5` 是一个**带黄调的暖灰**（R=247 > B=245）。而独立 HTML 打开时，
浏览器默认背景是 `#FFFFFF` 纯白。两块底挨着同一个卡片看，暖灰底会让卡片显得"偏黄"，
纯白底则让卡片显得"偏冷" —— **这是同时对比（simultaneous contrast）造成的视觉偏移，
不是颜色值变了**。

### 硬核验证

把 App 的 `--xw-bg` 从 `#ffffff` 一路改成 `#f7f7f5` → `#f3f0eb` → `#000000`，
卡片内部五个色值**全部纹丝不动**：

```
App背景=#ffffff  → sec rgb(252,250,255) / choice rgb(255,255,255) / border rgba(107,78,158,.2)
App背景=#f7f7f5  → sec rgb(252,250,255) / choice rgb(255,255,255) / border rgba(107,78,158,.2)
App背景=#f3f0eb  → sec rgb(252,250,255) / choice rgb(255,255,255) / border rgba(107,78,158,.2)
App背景=#000000  → sec rgb(252,250,255) / choice rgb(255,255,255) / border rgba(107,78,158,.2)
```

这就是当初把色值写死、**不引用任何 `--xw-*` 变量**的目的 —— 换主题、换皮肤，卡片都不变形。

### 那要不要让卡片跟主题统一？

两种取向，看你想要哪个：

| | 卡片色值写死（当前） | 卡片跟随主题 |
|---|---|---|
| 换主题/皮肤 | 卡片始终一致，跟独立 HTML 完全对得上 | 卡片跟着变，可能又和你调好的设计不一样 |
| 与页面融合度 | 卡片会比周围"白"一档，有点浮起来 | 完全融入 |
| 风险 | 无 | 每个主题都要重新调一遍，容易再出偏差 |

当前是**前者**。如果你更想要"融进页面"的感觉，我可以把 `.sec` 的 `--panel`
从 `#FCFAFF` 接到 `--xw-paper` 上，让面板跟着主题走 —— 但按钮的 `#fff` 建议保留，
否则按钮会失去"卡片里可点的东西"这层层次。你说一声就改。

## 九、追加修复：App 内卡片与独立 HTML「长得不一样」（字体 / 字重 / 按钮底色 / 间距）

**现象**：同一台手机上，独立打开设计 HTML 是衬线宋体、按钮微微泛紫、
与面板融合；App 内却是黑体、字偏细、按钮死白、整卡显紫、内距更宽。

### 根因（四处，按影响排序）

1. **字体没钉死**（头号原因）。`.xw-plot-card` 原先不写 `font-family`，
   继承线下 App 根节点 `.miya-offline-app` 的 `--xw-sans`（"Jost","Noto Sans SC"
   黑体系）；且根节点带 `font-weight:300`，卡片文字被连带变细。
   独立 HTML 用的是 `"Noto Serif CJK SC","Songti SC",serif` 衬线栈。
2. **按钮底色写死 `#fff`**。设计稿是「白渐变叠在 `--panel` 淡紫面板上」，
   按钮与面板融合、微微泛紫；纯白按钮衬淡紫面板对比过强，
   视觉上整张卡「更紫」（这就是 App 截图偏薰衣草色的来源）。
3. **间距 / 圆角偏差**。`.sec` 内距 `16px 16px 14px`（设计 `10px 12px 12px`）、
   按钮圆角 `10px`（设计 `12px`）、◇/箭头 `18px`（设计 `16px`）、
   窄屏还额外收了 wrap/sec 边距（设计不收）。
4. **hover 态偏淡**。描边用 `rgba(107,78,158,.38)`（设计是实色 `--purple-l`），
   阴影层数与数值也不同。

### 修法

- `css/miya-offline-plot.css`：卡片根节点补 `font-family`（衬线栈）+
  `font-weight:400`；按钮底色改回「白渐变叠 `var(--panel)`」；圆角/内距/符号
  位置/窄屏媒体查询全部逐字对齐设计稿；hover 与 `:active` 同步用设计稿的
  亮紫描边 + 三层阴影。
- `js2/miya-offline-plot.js`：与字号强绑定同一套路 ——
  root/wrap/sec/标题/按钮逐层内联 `font-family` + `font-weight !important`。
  原因：用户启用自定义字体时，`style.css` 有
  `html.miya-custom-font-active body :where(:not(...)×5) { font-family: var(--miya-font) !important }`，
  CSS 文件里怎么写都压不过，只有内联 `!important` 稳赢。
  **⚠️ 内联字体名必须用单引号**：拼进 `style="..."` 双引号属性里，
  字体名若也用双引号，第一个 `"` 就截断 style 属性，整条声明失效
  （实测踩过：computed 落回全局字体，卡片又变黑体）。
- `index.html`：`miya-offline-plot.css?v=11`、`miya-offline-plot.js?v=5`（破缓存）。

## 十、追加修复：「预览有质感、App 里没有」—— 默认态阴影从未交付

**现象**：并排对比独立预览与 App 内卡片，预览的按钮明显「浮」在面板上、
有光影层次；App 里是死白一片、完全扁平。

### 根因（这次是真正的最后一块）

1. **按钮默认态三层阴影从未写进交付 CSS**（质感核心）：
   `0 1px 1px`（近影定边）+ `0 6px 16px -12px`（远处弥散托底）+
   `inset 0 1px 0`（顶部内高光）。之前只写了 hover/active 的阴影，
   默认态一直是空的 —— 按钮没有「浮起」，自然没有质感。
2. **按钮字号钉错**：交付钉 14px（窄屏 13.5px），设计稿实际是
   `.94em×16px=15.04px`（窄屏 `.93em×16px=14.88px`），
   整卡文字比预览小一圈。现统一钉 15px。
3. **◇ 符号偏小**：钉死 13px，设计稿 `1.05em≈15.8px`，改为 `1.05em` 随按钮走。
4. **箭头滑入机制不对**：用 `right:16→15px` 位移，设计稿是
   `translateX(-3px)→0` 缓动滑入，已按设计稿重写。
5. **hover/active 多了 `background-color` 变化**（设计稿没有），已删。
6. **按钮间距 8px**，设计稿 `.body` gap 是 10px，已改。
7. `:active::before` 与 hover 对齐（opacity 1 + scale 1.08）。

### 部署可靠性加固（SW 整包重建）

  `BUILD 'sw-53' → 'sw-54'`；`index.html` 的 `<meta name="miya-sw-build">` 同步 sw-54。
