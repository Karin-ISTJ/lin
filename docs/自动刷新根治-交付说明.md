# 网页自动刷新根治 · 交付说明

> 对应反馈：「不知道为什么网页容易自动刷新。」

## 一、根因

刷新源只有一处：版本哨兵（`js1/app.js`）。它收到 SW 广播的构建号后与页面
`<meta name="miya-sw-build">` 比对，**SW 比页面新就直接 `location.reload()`**
（sessionStorage 保证一次会话最多一次）。问题出在弱网/慢服务器下的连锁反应：

1. 页面 HTML 本身走 SW 的 networkFirst：网络 **400ms 内回不来就用缓存旧版顶上**；
2. 于是页面 meta 落后于 SW 的 BUILD → 哨兵判定"有新版" → **立即刷新**；
3. 但刷新后加载 HTML **再次 400ms 超时**、再次用缓存顶上 —— meta 依旧落后；
4. 更糟的是 reload 会**掐断第一次加载还在后台写缓存的网络请求**，
   缓存里的 HTML 永远更新不了；
5. 结果：**每个新会话（每次打开 App）首开都自动刷一次** —— 即"容易自动刷新"。

加重因素：此前 `miya-sw-build` meta 连续多轮发版没跟着 BUILD 走（一直卡在
sw-72），用户缓存里 HTML 的 meta 长期大幅落后，把这个循环踩了个满上
（该 desync 上一轮已修复同步，但循环机制本身还在）。

## 二、修复：盲刷 → 确认式刷新（两步握手）

**页面端（`js1/app.js` v=99）**：发现 SW 比自己新时不再直接 reload，而是
向 SW 发 `miya-prepare-reload`，等回执；只有回执确认「缓存里已经是
更新的文档」才刷新。任何失败（离线/慢网/拉到的文档没更新/8 秒超时）
都安静放弃本会话 —— 下次导航的 networkFirst 后台会自然把缓存补齐。

**SW 端（`sw.js` BUILD sw-77）**：新增 `miya-prepare-reload` 处理：
SW 自己 fetch 最新 index.html（no-cache 直连网络，不经过自身 fetch handler）、
校验文档里的 meta 确实比页面新、**等 put 落盘后**才回执 `miya-reload-ready`。
落盘等 待是关键：页面收到回执就 reload，不能让它读到半旧的缓存。

**为什么不会漏更新**：JS/CSS 的新鲜度根本不依赖这次刷新 —— SW 缓存 key
剥离查询串，旧 HTML 引用 `xxx.js?v=旧` 命中的也是磁盘上的新内容；
刷新只服务"HTML 本身有 DOM 变更"的场景，而那正是握手能确认的部分。

**收敛性**：刷新后页面 meta = SW BUILD，之后比对条件永远不成立，
同一版本最多刷一次；失败场景则一次都不刷。

## 三、版本同步

| 项 | 值 |
|---|---|
| `js1/app.js` | `?v=98 → 99`（哨兵改两步握手，含 8s 超时兜底与监听器清理） |
| `sw.js` | `BUILD: sw-76 → sw-77`（新增 miya-prepare-reload） |
| `index.html` | `miya-sw-build` meta 同步 `sw-77`；app.js 引用 `?v=99` |

## 四、验证

**Node 单测 13/13 通过**（`_test_reload.js`）：

- SW 端：拉到新 HTML → put 落盘 → 回执 meta；404 / 离线异常 / 文档无 meta
  → 回执 0；`miya-get-build` 询问不受影响
- 页面端：回执确认更新 → 刷新+写标记；回执未更新 → 不刷+写标记；
  SW ≤ 页面 → 无动作；会话已刷过 → 跳过；无 controller → 放弃；
  meta 缺失 → 无动作；8s 无回执 → 超时放弃；回执后超时器取消

**真实浏览器 E2E（headless Chromium + 延迟 1.5s 的慢 HTML 服务器，模拟弱网）**：

- 服务器文档未更新时：哨兵握手 → 确认拉到的还是旧文档 → **零刷新** ✅
- 服务器升级后：页面拿到新版 meta 同步，无多余刷新 ✅
- 重复访问：持续稳定，BUILD 相同时哨兵直接早退，无握手请求 ✅

## 五、使用提示

- 已装旧版的用户联网打开一次即可完成更新；**这次刷新后会彻底安静**
  （meta 已同步 sw-77，后续只有真正发新包时才会再刷一次）。
- 另有一类"假刷新"与本机制无关：手机切后台太久被系统回收内存，
  回来时页面重载 —— 表现是切回 App 时白屏一两秒后重现，而不是打开后
  1~2 秒内闪一下。若仍遇到后者再来找我，但修复后不应再出现。
