# 拉取模型闪烁根治 & 副线路移除 · 交付说明

> 对应反馈：
> ①「对话 API 拉取模型，点那个框会闪一下，应该是拉取了两次，每次都这样」
> ②「副线路删掉吧，不需要」

## 一、拉取模型「闪一下」：双渲染根治

### 根因

`fetchChatModels`（`js1/miya-chat-contact-settings.js`）是 stale-while-revalidate 写法：

1. 点 ⟳ → **先用缓存 `applyOptions` 重写一次下拉**（还弹一次 toast「已获取 N 个模型」）；
2. 网络结果回来 → `applyOptions` **再重写一次**（再弹一次 toast）。

而进入面板时 `modelSelectHtml` 已经用**同一份缓存**把列表填进下拉了 ——
点 ⟳ 前屏幕上本来就有这份列表，预渲染等于把同样的列表连写两遍。
用户看到的正是：下拉内容跳变（闪一下）+ toast 连弹两次，每次点都如此。

### 修复

**只渲染一次**：

- 网络成功 → 渲染 + toast（一次）；
- 网络失败 → 缓存列表本来就在下拉里，提示「获取失败，已保留现有列表」，不再动 DOM；
- 失败且无缓存 → 维持原有错误提示。

顺带把缓存预渲染那段历史注释（讲旧参数错位的）一并移除 —— 那段逻辑已整体不存在。

## 二、副线路移除

### 移除前先说清一个事实

排查发现副线路的「自动切换」**在当前版本里从未真正生效过**：配置层保存的字段是
`fallbackEnabled / fallbackBaseUrl / …`，而引擎读取的是 `cfg.fallbackToSecondary` +
`cfg.secondaryApi`（全项目没有任何地方写入这两个字段）—— 字段名断裂，fallback 分支
永远走不进去。所以删除它是纯粹的死代码清理，**零行为变化**。

### 清理范围

| 文件 | 内容 |
|---|---|
| `js1/miya-chat-contact-settings.js` | 「对话 API」面板整段副线路卡片（网关/密钥/模型/温度/自动切换开关）；表单保存、预设快照/载入/导出里的全部 `fallback*` 字段；`#mq-api2-*` 事件绑定、温度联动、模型草稿 state |
| `js1/miya-chat-engine.js` | `resolveChatApiSlice` 的 useSecondary 分支、`hasSecondaryApiConfigured`、`callWithSlice/callSliceGuarded` 的 usedSecondary 参数、`_usedSecondaryApi` 标记、主→副 fallback catch |
| `js1/miya-couple-whisper-engine.js` | 同款 fallback 链路（深夜私语引擎）+ `secondary_api_not_configured` 错误分支 |
| `js2/miya-api-bridge.js` | `resolveSecondaryApiConfig` 及导出 |
| `js2/miya-api-config.js` | 注释措辞更新 |

- 旧配置 / 旧预设文件里残留的 `fallback*` 字段：读取时自然忽略，**无需迁移**；
- 「接口预设」下拉、⟳ 拉取模型、温度滑块等其余功能不受影响。
